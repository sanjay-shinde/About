Complete MFA Challenges for Automation Users

By Sanjay Shinde · Sep 2026 · 7 min read MFA TOTP Automation

Multi-factor authentication (MFA) is mandatory for Salesforce logins — which is great for security, but it can break automated processes that log in through the UI: test automation, RPA bots, screen-scraping jobs, and monitoring scripts. The clean way to solve this is to give the automation user a time-based one-time password (TOTP) authenticator and generate the verification code programmatically. Here's how.

💡

Prefer API auth when you can. If your integration can use the Salesforce APIs directly, use an OAuth flow — the JWT Bearer or Client Credentials flow — which is not subject to interactive MFA. Use the TOTP approach below only for automation that genuinely has to complete the UI login challenge.

Why automation users hit MFA

MFA challenges the interactive login. A human normally reads a 6-digit code from an authenticator app (Salesforce Authenticator, Google Authenticator, etc.) and types it in. An automated process has no human to do that — so it stalls at the verification screen. The fix is to register an authenticator for the automation user, capture the underlying shared secret, and have your automation compute the same 6-digit code the app would have shown.

How TOTP works (in one paragraph)

TOTP (RFC 6238) derives a short code from two inputs: a shared secret (a Base32 string you get once, at setup) and the current time. The current Unix time is divided into 30-second windows; that window number is HMAC-SHA1–hashed with the secret, then truncated to a 6-digit number. Because both Salesforce and your code use the same secret and the same clock, they compute the same code — no network round-trip needed. Salesforce's defaults are 30s period, 6 digits, SHA1.

Step 1 — Register an authenticator & capture the secret

  1. Log in as the automation user and open Settings → Personal → Advanced User Details (or your org's app-registration path for the One-Time Password Generator).
  2. Choose to connect / register an authenticator app. Salesforce shows a QR code and a text shared key.
  3. Instead of scanning the QR, copy the Base32 shared key — this is what your code needs. (It looks like MCAA7REYNQ4L6DYQEVTAXAK7RGANQHOY.)
  4. Finish registration by entering one valid code (you can generate it with the snippets below) so Salesforce binds the authenticator to the user.
🔐

Treat the shared secret like a password. Anyone with it can generate valid codes. Store it in a secrets manager / environment variable — never hard-code it in source or commit it to Git. The hard-coded values below are for illustration only.

Step 2 — Generate the TOTP code in your automation

Pick your stack. Each snippet takes the Base32 secret and returns the current 6-digit code, which your automation then submits at the Salesforce verification prompt. 

// npm install otplib
const { authenticator } = require('otplib');

// Base32 shared secret from Salesforce — load from env, never hard-code
const TOTP_SECRET = process.env.TOTP_SECRET;

function getTotpCode() {
  if (!TOTP_SECRET) {
    throw new Error('Missing TOTP_SECRET');
  }
  // 30s period / 6 digits / SHA1 are the defaults — matches Salesforce
  return authenticator.generate(TOTP_SECRET);
}

import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;
import java.nio.ByteBuffer;
import java.security.GeneralSecurityException;
import java.time.Instant;

public class Totp {

    // Load from env/secret store in production
    private static final String TOTP_SECRET = "MCAA7REYNQ4L6DYQEVTAXAK7RGANQHOY";

    public static String getTotpCode() throws GeneralSecurityException {
        if (TOTP_SECRET == null || TOTP_SECRET.isEmpty()) {
            throw new IllegalArgumentException("Missing TOTP_SECRET");
        }
        byte[] keyBytes = decodeBase32(TOTP_SECRET);
        long timeInterval = Instant.now().getEpochSecond() / 30; // 30s step
        return generateTOTP(keyBytes, timeInterval, 6);
    }

    private static String generateTOTP(byte[] key, long time, int digits)
            throws GeneralSecurityException {
        byte[] data = ByteBuffer.allocate(8).putLong(time).array();
        Mac mac = Mac.getInstance("HmacSHA1");
        mac.init(new SecretKeySpec(key, "RAW"));
        byte[] hash = mac.doFinal(data);

        int offset = hash[hash.length - 1] & 0xF;
        int binary = ((hash[offset] & 0x7F) << 24)
                   | ((hash[offset + 1] & 0xFF) << 16)
                   | ((hash[offset + 2] & 0xFF) << 8)
                   |  (hash[offset + 3] & 0xFF);
        int otp = binary % (int) Math.pow(10, digits);
        return String.format("%0" + digits + "d", otp);
    }

    // RFC 4648 Base32 alphabet
    private static byte[] decodeBase32(String base32) {
        String ALPHABET = "ABCDEFGHIJKLMNOPQRSTUVWXYZ234567";
        String s = base32.trim().toUpperCase().replaceAll("=", "");
        byte[] bytes = new byte[s.length() * 5 / 8];
        int buffer = 0, bitsLeft = 0, index = 0;
        for (char c : s.toCharArray()) {
            int val = ALPHABET.indexOf(c);
            if (val == -1) throw new IllegalArgumentException("Invalid Base32 char: " + c);
            buffer = (buffer << 5) | val;
            bitsLeft += 5;
            if (bitsLeft >= 8) {
                bytes[index++] = (byte) (buffer >> (bitsLeft - 8));
                bitsLeft -= 8;
            }
        }
        return bytes;
    }

    public static void main(String[] args) throws Exception {
        System.out.println("code: " + getTotpCode());
    }
}
using System;
using System.Security.Cryptography;

public class Program
{
    // Load from env/secret store in production
    private const string TOTP_SECRET = "MCAA7REYNQ4L6DYQEVTAXAK7RGANQHOY";

    public static string GetTotpCode()
    {
        if (string.IsNullOrEmpty(TOTP_SECRET))
            throw new ArgumentException("Missing TOTP_SECRET");

        byte[] key = DecodeBase32(TOTP_SECRET);

        // 30-second step as an 8-byte big-endian value
        long timeStep = DateTimeOffset.UtcNow.ToUnixTimeSeconds() / 30;
        byte[] timeBytes = BitConverter.GetBytes(timeStep);
        if (BitConverter.IsLittleEndian) Array.Reverse(timeBytes);

        using var hmac = new HMACSHA1(key);
        byte[] hash = hmac.ComputeHash(timeBytes);

        int offset = hash[^1] & 0x0F;
        int binary = ((hash[offset] & 0x7F) << 24) |
                     ((hash[offset + 1] & 0xFF) << 16) |
                     ((hash[offset + 2] & 0xFF) << 8) |
                      (hash[offset + 3] & 0xFF);

        return (binary % 1000000).ToString("D6");
    }

    // RFC 4648 Base32 alphabet
    private static byte[] DecodeBase32(string input)
    {
        const string alphabet = "ABCDEFGHIJKLMNOPQRSTUVWXYZ234567";
        string clean = input.TrimEnd('=').ToUpperInvariant();
        byte[] output = new byte[clean.Length * 5 / 8];

        int buffer = 0, bitsLeft = 0, index = 0;
        foreach (char c in clean)
        {
            int val = alphabet.IndexOf(c);
            if (val == -1) throw new ArgumentException($"Invalid Base32 char: {c}");
            buffer = (buffer << 5) | val;
            bitsLeft += 5;
            if (bitsLeft >= 8)
            {
                output[index++] = (byte)(buffer >> (bitsLeft - 8));
                bitsLeft -= 8;
            }
        }
        return output;
    }

    public static void Main() => Console.WriteLine($"code: {GetTotpCode()}");
}
🛠️

What I fixed vs. common copy-paste versions: the Base32 decoder must use the RFC 4648 alphabet ABCDEFGHIJKLMNOPQRSTUVWXYZ234567 — not a placeholder string — or decoding silently produces wrong codes. The Node.js sample uses otplib's authenticator.generate(), whose defaults (30s / 6 digits / SHA1) already match Salesforce.

Step 3 — Feed the code into your login flow

Wherever your automation drives the browser (Selenium, Playwright, Puppeteer) or replays the login, call the function above at the moment the verification prompt appears and type the returned code. Because codes rotate every 30 seconds, generate it immediately before submitting — don't cache it.

Gotchas & best practices

  • Clock sync matters. TOTP depends on time. Keep your automation host's clock synced via NTP, or codes will be rejected.
  • Handle the boundary. If you generate a code in the last second of a window, it may expire before submission. Regenerate right before use, and be ready to retry once.
  • Secure the secret. Environment variable or secrets manager — never in source control.
  • Least privilege. Scope the automation user's permissions tightly and monitor its logins.
  • Reconsider the approach. If this is an API integration, switch to OAuth (JWT Bearer / Client Credentials) and skip interactive MFA entirely.
The goal isn't to weaken MFA — it's to let a trusted, tightly-scoped automation identity satisfy the same challenge a human would, in a way you fully control.
